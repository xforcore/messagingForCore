## messagingForCore 0.1.0

The first release: Microsoft's System.Messaging (.NET Framework 4.8 Reference Source) on .NET 10, on Linux, Windows
and macOS, with local private queues stored in SQLite (issue #1).

- **Packages:** `messagingForCore` (references `messagingForCore.Messaging`, System.Messaging 4.0.0.0 with Microsoft's
  public key token b03f5f7f11d50a3a) and the setup tool `messagingForCore.Msmq` (`messagingforcore-msmq`).
- **The queue store:** MSMQ's runtime is replaced, function for function, by managed code that keeps queues and
  messages in one SQLite database per machine, named by `MESSAGINGFORCORE_DB` and prepared by
  `messagingforcore-msmq install`. Private queues; send, receive and peek with timeouts; cursors and enumerators; by
  ID, correlation ID and lookup ID; `BeginReceive`/`BeginPeek`; `MessageQueueTransaction` and `Single`;
  `XmlMessageFormatter`, `BinaryMessageFormatter` and `ActiveXMessageFormatter`'s primitive types.
- **BinaryMessageFormatter** uses webForCore's `webForCore.Serialization.Formatters` 0.10.0, from webForCore's feed.
- **Not supported**, each failing with a `MessageQueueException` that names it: remote and public queues, Active
  Directory, network format names, DTC (`Automatic` in a transaction scope), queue security, COM bodies. Nothing calls
  MSMQ, on Windows either.
- **Tests:** messagingForCore's own 68, 8 two-process gate tests and Mono's 87, on Linux and Windows: 161 pass, 2 known
  failures (Active Directory, and a code access security difference).
- **.NET Framework compatibility:** bodies written by .NET Framework 4.8's XmlMessageFormatter and
  BinaryMessageFormatter read on messagingForCore, and the reverse (CI's Windows runner); binary bodies are byte for
  byte the same.
